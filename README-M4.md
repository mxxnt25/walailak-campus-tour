# M4 — จบการนำเที่ยวได้ทันทีแบบเดิม

เริ่มอ่านไฟล์นี้ก่อนใช้งานชุดโค้ดนี้

## สถานะ

ทำส่วนตารางทัวร์ ไกด์ และ Admin Route CRUD แล้วตามรายการใน `docs/m4/HANDOFF.md`
**ยังไม่ใช่ Final QA sign-off และยังไม่ควรนำขึ้น production**:
- กติกาล่าสุด: ไกด์ที่รับงานแล้ว หรือ ADMIN/SUPER_ADMIN กดจบทัวร์ได้ทันที ไม่ต้องรอเวลาเริ่มหรือสิ้นสุด โดยรอบต้องเป็น OPEN/FULL/CLOSED และยังต้องยืนยันการจบ
- กติกาทับซ้อนที่ผู้ใช้ยืนยันแล้ว: งาน ASSIGNED/ACCEPTED ชนกันเมื่อช่วงเวลาทับกันจริง `[start,end)`; จบ 11:00 เริ่มงานถัดไป 11:00 ได้ ไม่มี buffer เดินทาง ไม่ต้องเผื่อเวลาเดินทาง
- ไม่มีส่วนกลาง M5/M6 ใน ZIP ต้นทาง จึงใช้ adapter เฉพาะ M4 เพื่อไม่แก้ไฟล์ของคนอื่น
- ต้องทดสอบกับ Supabase ของทีมและบัญชีจริงอีกครั้ง รวมการทำงานพร้อมกันหลาย session

## วิธีนำไปทดสอบ

1. แตก ZIP นี้เป็นโฟลเดอร์ใหม่ ไม่ทับไฟล์งานที่ยังไม่ commit ของเพื่อน
2. อ่าน `docs/m4/HANDOFF.md` และให้ integration owner ตรวจ migration sequence ว่า `0018`–`0020` ไม่ชนงานทีมใน branch รวมล่าสุด
3. ใช้ฐาน Supabase สำหรับทดสอบที่มี baseline ผ่าน `0017` แล้ว ตรวจ `docs/m4/VERIFY.sql` ส่วน BEFORE ก่อน
4. ถ้าลง `0019` แล้ว ให้รันเฉพาะ `supabase/migrations/0020_m4_restore_immediate_completion.sql` ในฐานทดสอบ ถ้ายังไม่ลงชุด M4 ให้ลง migration ตามลำดับ `0018` → `0019` → `0020` อย่าแก้หรือลบไฟล์ migration เก่า
5. สร้าง `.env` ในเครื่องจาก `.env.example` ใส่ URL กับ publishable key ของฐานทดสอบเอง ไม่ใช้ service-role key
6. เปิด terminal ที่โฟลเดอร์โปรเจกต์ แล้วรันทีละคำสั่ง:

```sh
npm ci
npm run build
npm run dev
```

7. เข้าด้วยบัญชีแอดมิน: ทดสอบสร้างรอบอนาคต/ย้อนหลัง/เวลาไม่ถูกต้อง มอบหมายไกด์ชนเวลา และแก้จุดแวะ
8. เข้าด้วยบัญชีไกด์: ทดสอบรับงาน ปฏิเสธงาน โหลดหน้าใหม่ เช็กชื่อ และดูรายชื่อ
9. ใช้รายการ `docs/m4/HANDOFF.md` ส่งผลจริงให้ M2 หลัง integration

อย่าส่ง `.env` หรือข้อมูลลับกลับมา ไฟล์ชุดนี้ไม่ได้เชื่อมต่อหรือแก้ฐานข้อมูลจริงของคุณ

## การเปลี่ยนแปลงล่าสุด

ยกเลิกการรอเวลาสิ้นสุดทั้ง UI และ Backend ด้วย migration 0020 โดยคืน logic เดิมของ complete_tour: ตรวจสิทธิ์ ตรวจสถานะ อัปเดตรอบ/งานไกด์/การจอง และบันทึก audit ใน transaction เดียว รอบ CANCELLED หรือ COMPLETED ยังกดจบซ้ำไม่ได้ ไม่เปลี่ยน validation ตอนสร้างตาราง การจองรอบหมดเวลา หรือป้องกันไกด์ทับซ้อน

## ไฟล์สำคัญ

- `docs/m4/HANDOFF.md` — สิ่งที่แก้ ผลทดสอบ ข้อจำกัด และสิ่งที่ต้องประสานทีม
- `docs/m4/VERIFY.sql` — query ตรวจฐานข้อมูล ไม่มีการลบข้อมูล
- `docs/m4/ROLLBACK.sql` — แผนย้อนกลับเมื่อจำเป็น ใช้หลังคืน frontend รุ่นก่อน และประสาน integration owner
- `docs/m4/M4-changes.patch` — patch เฉพาะโค้ด/SQL M4 สำหรับตรวจและนำไป apply บน baseline ที่ตรงกัน
- `tests/m4/` — automated tests
- `docs/m4/*-results.txt` และ `screenshots/` — หลักฐานการทดสอบ
